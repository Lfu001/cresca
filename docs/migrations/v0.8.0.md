# Migrating to v0.8.0

v0.8.0 changes naming-hook input from source and target command-line arguments to standard-input JSON.

## When migration is required

The affected releases run from v0.5.0, which introduced naming hooks, through v0.7.1, the latest release with the argument-based interface. Upgrading directly from any of these releases to v0.8.0 follows the same steps; upgrading to v0.7.1 first is not required.

| Existing configuration in v0.5.0–v0.7.1 (inclusive) | Action when upgrading to v0.8.0 |
| --- | --- |
| A naming hook that depends on the appended source and target arguments, including their values, positions, or count | Stop expecting appended arguments; read any branch inputs you need from standard-input JSON. |
| A naming hook that works without the appended arguments, such as one that always prints a fixed name | No script change required for this input change. |
| No configured naming hook | None. Built-in naming continues to work. |

Complete any required script changes when upgrading to v0.8.0, before creating a new review with your naming hook. Both positional review and `review --pr` use the new naming input. When Cresca selects an existing review, it bypasses the naming hook, so resuming that review does not verify whether your script has been migrated.

This naming-hook input change requires no manual edits to stored review metadata or approvals. Configuring a PR resolver is optional for positional review.

## Update the naming script

1. Remove expectations about appended source and target arguments. Read any branch inputs you need from the JSON fields below; standard input contains one UTF-8 JSON object followed by EOF.
2. Verify the migrated script with the sample JSON below.
3. Upgrade Cresca to v0.8.0 and activate the migrated script together.

| Contract | v0.5.0–v0.7.1 | v0.8.0 |
| --- | --- | --- |
| Command line | `<program> <configured args...> <source> <target>` | `<program> <configured args...>` |
| Source | Appended argument | `branches.source` in standard-input JSON |
| Target | Appended argument | `branches.target` in standard-input JSON |
| Original PR identifier | Unavailable | `request.pr` in PR mode; `request` is empty in positional mode |
| Resolver information | Unavailable | `metadata` object; empty when absent or in positional mode |
| Output | One valid UTF-8 Git branch-name line | Unchanged |

The `program` and fixed `args` settings stay the same. Fixed arguments retain their positions; only the dynamically appended source and target arguments disappear.

For example, a shell hook without fixed arguments previously read:

```sh
#!/bin/sh
set -eu
source=${1#feature/}
target=$2
printf '%s-into-%s\n' "$source" "$target"
```

Replace it with this script, which requires `jq`:

```sh
#!/bin/sh
set -eu
jq -r '.branches | "\(.source | sub("^feature/"; ""))-into-\(.target)"'
```

To check the migrated script independently, replace `/Users/me/bin/cresca-review-name` with your configured program and include any fixed arguments:

```sh
printf '%s\n' '{"request":{},"branches":{"target":"main","source":"feature/login"},"metadata":{}}' \
  | /Users/me/bin/cresca-review-name
```

The expected output is `login-into-main`, followed by a newline. This checks the new input format without preparing a review. The output must still be a valid Git branch name for the branch inputs your script handles.

For PowerShell hooks, remove the dynamic source and target parameters and read `[Console]::In.ReadToEnd() | ConvertFrom-Json`. Keep any parameters corresponding to configured fixed arguments. See [Advanced Usage](../advanced-usage.md#customizing-review-branch-names) for the complete PowerShell example and PR-mode JSON input.
